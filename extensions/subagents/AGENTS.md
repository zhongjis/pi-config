## Purpose

Run isolated Agent sessions with foreground results and background supervision. See [CONTEXT.md](CONTEXT.md) for agent-graph terminology.

## Ownership

- Owns agent discovery, execution, steering/resume, notifications, the typed `agent_graph` graph runtime (`src/graph/`), and local UI/tests.
- Agent definitions remain outside this runtime; shared utilities belong to [lib](../lib/AGENTS.md).
- `src/index.ts` owns activation order, manager/registry ownership, live settings/appliers, UI composition, lifecycle hooks, and registration. Extracted modules MUST NOT import it.
- Only the activation that owns the manager registry MAY mutate shared lifecycle state; non-owning child activations still register tools, no-op start/switch, and dispose only their local manager, fleet, widget, notifications, and usage state on shutdown.
- `src/graph/graph-runtime.ts` owns graph tasks/runs, session history, execution/resume/stop, typed graph tools, completion snapshots, and the fleet adapter. `gate-handoff.ts` owns correlated human requests and response receipts; `gate-tool.ts` owns resolution registration; `gate-notifications.ts` owns held actionable nudges.
- `src/graph/graph-actor.ts` owns the root run lifecycle, native child hierarchy, serialized persistence, control acknowledgments, and drain-before-terminal selection; its context is an owned mutable aggregate ([ADR 0004](../../docs/adr/0004-graph-actor-context-is-an-owned-mutable-aggregate.md)). `run-graph.ts` is only the create/start, AbortSignal bridge, `toPromise`, and cleanup adapter.
- `src/graph/trace.ts` owns the per-run trace and runtime inspection log writers; `replay.ts` owns pure trace replay/diff and `replay-command.ts` the `/agent-graph-replay` command. `src/output-file.ts` `sessionArtifactPath`/`createSessionArtifactPath` own exact-session artifact paths.
- `node-lifecycle.ts` owns typed agent/human lifecycle machines; `node-effects.ts` owns single spawn/gate/prompt invokes. `graph-domain.ts` owns the single `SchedulerState` projection and applies root-selected transactions. `graph-planner.ts` queries are pure; `GraphProjection` is a read-through view, not a second lifecycle/status map.
- `subgraph-actor.ts`, `expand-actor.ts`, `fanout-actor.ts`, and `feedback-actor.ts` own volatile coordinator sequencing; root transactions remain the sole planner, topology, checkpoint, control, and terminal authority. `bounded-feedback.ts` retains pure durable types, decision/schema validation, bounds, continuation, and terminal proposals.
- `coordinator-protocol.ts` defines immutable resolver-free COORD receipts, full-operation ACKs, and root-owned prepared/committed replay journals. Expand admission (including restored running identity) commits before actor creation; expand/fanout/feedback coordinators consume no executor/resource slot but retain native ownership through explicit release or infrastructure drain.
- ExpandActor prepares source/namespace validation, requests atomic insertion or ordinary node failure, awaits the containing checkpoint ACK, then completes RELEASE_READY → RELEASE → RELEASED. Root revalidates current collisions and the 500-node effective limit before inserting definitions, edges, identities, and `{}` settlement in one checkpoint. Dynamic registrations precede updates/admission after commit.
- Restored running expands recompute authoritative resolved source without incrementing attempt/identity; committed settled expands create no actor. Whole-run cancellation commits before COORD.CANCEL and suppresses pending insertion; lifecycle cancellation preserves interrupted running evidence. Active expand skip/retry remains unsupported. Infrastructure FAIL drains without further writes. Panda v2 is unchanged.
- FanoutActor and generated leaf actors are native root siblings. FanoutActor requests atomic materialization, consumes bounded committed owner views, requests ordered all-settled aggregation, and releases only after ACK. Root validates the entire batch against current topology/run bounds, assigns definitions/UUIDs/provenance/ordinals/ownership, and checkpoints before registration or leaf dispatch. Existing collections attach without preparation or identity/attempt changes; settled owners create no actor.
- Fanout coordinators use no executor slots; root retains each leaf independently through NODE release even after collection settlement. Pause does not block active collection aggregation or drain; active ordinary fanout owner skip/retry remains unsupported and leaf controls remain available. All ordinary and feedback work collections use FanoutActor; no automatic root aggregation remains.
- FeedbackActor, every work FanoutActor, evaluator and item leaf are direct root siblings. Feedback consumes bounded committed owner views and requests initial intent, complete atomic iteration materialization, and decision transactions through COORD; both ACK and progressed committed facts precede successor requests. Root checkpoints running admission before spawn; absent-state admissions and restored active owners retain attempts/IDs. Terminal owners create no actor.
- Feedback materialization commits work/evaluator/items, ownership, definitions, UUIDs, provenance/ordinals and active state together; work FanoutActor attaches without allocating. Decision/history and continuation intent commit separately before successor allocation. Whole-run cancellation atomically normalizes feedback and leaf dispositions before signaling and waits all independent drains/releases; lifecycle cancellation remains resumable. Active feedback owner skip/retry is unsupported.
- Feedback `retryFailures` counts accepted evaluator failures, not admissions or cancellations. `retryError` exists exactly when that count is positive. Same-evaluator checkpoints append at most one failure, must match newly appended failure outcomes for that exact instance, and cannot rewrite an unchanged count's error; only a new evaluator materialization resets evidence to zero. Fresh protocol-v1 restore requires the exact failure-outcome count; a deterministic legacy baseline permits only historical uncertainty bounded by that evaluator's baseline admissions, never missing post-baseline failures. Execution-ledger accounting remains the repair-budget authority.
- `node-protocol.ts` defines production resolver-free NODE messages and immutable admission receipts. Root-owned per-incarnation journals separate prepared ACKs from committed replay and compare duplicates before current-correlation validation. Admission handoff follows checkpoint; repair atomically drains the old execution and admits its successor within the absolute budget.
- Native typed child ownership retains capacity and excludes same-ID admission through settlement ACK, RELEASE_READY, RELEASE, and RELEASED. Root removes children/journals only after explicit release completion or physical failure drain. Cancellation persists exact disposition before CANCEL; pending gate/repair requests still receive ACK without follow-up effects. Durable cancellation supersedes an already-in-flight normal settlement proposal.
- `src/notification-coordinator.ts` owns held nudges, smart batches, grouped/individual delivery, and pending-nudge cancellation; lifecycle cleanup ordering remains activation-owned.
- `src/agent-tool.ts` and `src/result-tools.ts` own complete tool definitions; `src/agent-result.ts` shares foreground/retrieval/resume report semantics. `src/graph/result-observer.ts` owns graph-result subscribers; graph runtime owns their task lookup and terminal signaling.
- `src/invocation-config.ts` owns shared Agent config/model/thinking/scope preparation; direct and graph callers retain their own max-turn policy, warnings, delivery, and orchestration.
- `src/ui/agents-menu.ts` owns agent navigation, CRUD, and authoring wizards. `src/ui/conversation-overlay.ts` owns opening live and read-only history conversation viewers and their failure notices; `src/ui/conversation-viewer.ts` owns transcript rendering, search, and jump navigation. `src/ui/settings-menu.ts` owns presentation/input only; setting mutation and persistence remain in activation.
- `src/ui/agent-monitor.ts` owns the `/agent-monitor` overlay: agent-graph-run and independent-agent sections, session-history ordering, filter, routing, and the graph-only `o` detach. `src/ui/graph-run-panel-view.ts` hosts the observability panel as the in-Pi graph inspector.
- `src/agent-history.ts` owns reload-surviving independent-agent monitor history: session-local capture, defensive decode, and read-only child-transcript loading. Activation owns when capture starts, stops, and merges into the monitor.
- `src/agent-tool-scope.ts` owns subagent tool-scope narrowing (the live re-narrow on `turn_end` and `beforeToolCall` veto).
- `src/structured-output.ts` owns session-keyed capture storage (`rememberStructuredCapture`/`takeStructuredCapture`), retry/repair (`repairStructuredOutput`), and failure formatting (`structuredFailure`).

## Local Contracts

- Fresh descendants MUST inherit the parent's Agent-tree `local://` root, not its conversation by default.
- Terminal sessions remain resumable for 30 minutes in the current parent session; switch, reload, or shutdown may clean them sooner.
- Retention MUST remain bounded; resume is not durable-session availability. Reload-surviving monitor history is a read-only roster, not a resume target.
- Independent `persist_session` runs keep session-local `agent-history.json` keyed by the exact Pi session ID; forks start empty. Store only persisted independent runs, at most 50 and 1 MiB: a child JSONL path plus light metadata, never prompts, results, errors, or outputs. Capture at child-session creation and completion; disable and flush capture before lifecycle aborts. Interrupted running or queued rows display as stopped. History rows are read-only projections and MUST NOT be inserted into AgentManager. Read the transcript from the child JSONL without rewriting it. Persisted child sessions carry native `parentSession` lineage when the parent session file is known.
- Settled graph metadata history lives in session-local OS storage keyed by the exact Pi session ID, separate from Agent-tree sharing and graph resume checkpoints. Keep at most 20 unique runs, 200 nodes/run, 64 phases, 32 dependencies/node, 160-character sanitized display strings, and 8 MiB/session; evict oldest runs and disclose omitted nodes.
- History version 2 MAY retain sanitized display topology only: configured graph description, node kind/name/role, history-local parent/dependency/connection indices, iteration/item position, and feedback decision enums. It MUST contain no prompts, inputs, outputs, errors, outcome reasons, scripts, artifact paths, logs, bindings, UUIDs, runtime instance IDs, or conversation handles.
- Graph-owned transcript artifacts MAY provide historical prompt/outcome detail on demand while they remain in the exact session artifact area. Address them by deterministic run-ID plus history-index aliases; never persist their path, content, runtime agent ID, or availability in graph history.
- Live graph inspectors show complete retained node output. Reloaded history preserves hierarchy and configured graph description; unavailable artifact content remains explicitly disclosed.
- Load history before UI managers; capture completed/failed/explicit user-stopped runs before notification. Disable capture before lifecycle aborts and flush writes before replacing the session store. Version 1 remains readable and flat; unknown versions remain untouched with writes disabled; I/O failures emit only one generic warning per session.
- Rendering changes MUST preserve model-visible completion notifications and tool results. Collapsed completion notifications MUST flatten multiline previews and mark width clipping with an ellipsis; expanded previews retain their original content.
- Standalone notifications MUST use flat rows without `├─` or `└─`. `agent` call headers use the foreground format in both modes; background calls append only `[background]` beside the Agent identity.
- Completion notifications use lib's passive themed custom-message shell; it MUST NOT change their content or delivery path.
- Foreground results and background follow-up notifications MUST retain distinct delivery paths.
- Foreground capacity MUST remain independent of background capacity and unlimited by default; queued blocking callers MUST settle on completion, cancellation, startup failure, or shutdown. Detached spawns and resume bypass the foreground pool.
- `reportUsage` MUST default off and report each collected delta once through final tool results, including cache reads; display-token totals stay unchanged. Disabled/session-ended pools MUST retain no pending deltas.
- QoL's live manager-cost bridge remains independent of native reported usage; NEVER add both for the same spend. `showCost` MUST affect presentation only and default off.
- Run reports MUST derive model/thinking from SDK session getters, including inherited models and clamping/off.
- Queued/pre-session reports NEVER present requested model/thinking as actual execution.
- Omitted thinking MUST use SDK selected-model defaults, NEVER parent thinking.
- `thinkingDefault` MUST track configuration intent only; unknown intent stays unlabelled.
- `thinking: default (pending)` MUST survive queued retrieval until session metadata replaces it; resume retains session thinking.
- Foreground, retrieval, and resume MUST share structured result/error, transcript, and diagnostic details.
- `get_agent_result({run_id, wait?, verbose?})` routes independent agents and live-session `agr_*` graph runs without merging registries; details discriminate `agent` and `graph`. Graph waits use runtime signaling until a committed human request or terminal state; aborting retrieval MUST leave execution alive. `get_subagent_result({agent_id, wait?, verbose?})` retains its independent-agent contract.
- Human requests MUST publish only after their execution dispatch checkpoint commits, including every containing nested checkpoint. Requests expose an opaque execution-correlated `gate_id`, activation-local `revision`, gate kind, prompt and response schema; repeated retrieval NEVER consumes them. Persist no additional prompts or response history.
- `resolve_agent_graph_gate({run_id, gate_id, revision, response})` MUST validate current committed execution and the authored response schema. Identical accepted responses are idempotent within the activation; stale or conflicting responses fail. Reload reconstructs pending requests with new revisions and rejects all pre-reload responses, including nested gates; retrieve again before asking/resolving.
- The orchestrator MUST collect human input with `ask`, then resolve and retrieve again. Graph hosts NEVER call UI prompts. Unobserved gates receive one held follow-up nudge; retrieval cancels its pending nudge without consuming the gate. Lifecycle/terminal cleanup cancels nudges and settles subscribers; completion delivery remains unchanged.
- Compact `agent` and retrieval results MUST fit within three physical rows: status plus primary preview without redundant labels; available model (without `model:`) and thinking; configured expand hint. Queued IDs/next actions and pending thinking remain visible within the width budget.
- Turns, soft limit, tools, tokens, duration, estimated cost, and requested/effective discrepancies MUST appear only expanded; expanded reports retain complete answer/error before metadata and artifacts. Zero/unpriced costs stay omitted.
- Request provenance MUST survive resume; diagnostic model resolution MUST preserve execution policy and treat equivalent fuzzy identities as equal.
- Runtime diagnostics MUST remain visible expanded without counting as tool executions; expanded Run MUST explicitly show zero tools.
- Legacy/malformed details MUST retain full raw content expanded and obey the compact row budget.
- Runtime metadata MUST preserve non-runtime invocation tags; resume turns MUST count `turn_end`, not usage messages.
- Configured model chains MUST fail when exhausted; only absent model configuration inherits the parent.
- Hidden `subagent-model-fallback` MUST survive isolation/excludes and use lib's settlement coordinator for quota/rate-limit/access-denied recovery in the same transcript. Advance authenticated candidates without cycling; aborted signals/messages, overflow, other errors, and exhausted chains MUST stop recovery. Run/resume and structured-output repair MUST await final recovery idle; candidate thinking/Fast metadata replaces prior candidate defaults.

- Selected candidate `:fast` fixes Fast on; no suffix fixes off, NEVER inherited/session toggles. Validate explicit on before child creation; unsupported capability MUST NOT trigger fallback selection. Preserve selected metadata through `agent`/RPC/manager/runner; direct model options MUST NOT bypass frontmatter.

Open, combinator, or missing schemas NEVER error; node `input` and `outputs` ValueRefs are not path-checked.
- An `agent` repair respawn (execution sequence > 1) MUST append `Previous attempt <n-1> failed:` with the last 2000 failure characters and `Return a corrected result.` to the prompt; attempt 1 is unchanged. This memory is actor-local: restored executions use the original prompt, and NODE/COORD protocol, receipts, ledger, checkpoints and history are unchanged.
- Every `agent_graph` run writes `<runId>.trace.jsonl` to the exact-session task artifact area (`<tmpdir>/pi-subagents-<uid>/<encoded cwd>/<sessionId>/tasks/`, 0700 root), kept after settlement. JSONL v1: `header` (runId, startedAt, graph, input, per-node sha256 of canonical `outputSchema`), `node` `added`/`update` lines written only from post-commit publication callbacks, `resume`, `end`, and one `truncated` line at 8 MiB. Traces contain inputs and outputs (node-transcript privacy); NEVER record their path or content in graph history. I/O failure is non-fatal with one warning per session.
- `graphRuntimeTrace` MUST default false and is read at each run start. Invalid output, inability and executor/configuration failures MUST fail closed. `validation.gate` remains separate deterministic agent validation.

Monitor decision-source labels require both a successful completed projection and committed successful execution evidence; dispatching or waiting for a prompt, cancellation, dismissal and failure MUST NOT claim a human decision. Exposed output contains no provenance fields.
- Saved graph resolution accepts `.graph.json` and `.graph.yaml` through the same validation/runtime path. Roots remain ordered `.pi/agent-graphs`, `agent-graphs`, `.agents/agent-graphs`, then the global agent directory; same-name formats within one root fail as ambiguous. YAML accepts only JSON-compatible data, with duplicate keys, custom tags, and excessive aliases rejected.
- Root admission waves MUST checkpoint before native child creation. Settlement MUST use one delayed self-FLUSH per generation, checkpoint the bounded outcome/cost/drain batch, and only then remove children. Pause blocks admission, not settlement or pending skips. Control acknowledgments MUST use unique tokens and reject reentrant mutation/writer calls before sending; rejected controls MUST enqueue nothing.
- Root-owned SubgraphActor MUST explicitly own one native `graphLogic` child without adding depth. Running parent admission MUST commit before wrapper/child spawn. Root retains nested validation, ordinal/history assignment, recovery, disposition and buffered publication authority. Requests continue during cancellation/drain; settlement ACK then RELEASE_READY → RELEASE → RELEASED retains wrapper/parent capacity until physical drain and committed settlement.
- Nested graphs MUST be native `graphLogic` children of SubgraphActor. Their invocation-correlated, monotonic checkpoint request/ack protocol commits through the containing root transaction before acknowledgment or publication; matching duplicate sequences are idempotent and conflicting/reordered requests fail closed. Carry root depth 0 and reject depth above 32 before child creation and recursively on restore. Panda v2 remains authoritative; NEVER persist XState snapshots.
- The first infrastructure error MUST prohibit further dispatch/writes, cancel children, and propagate unchanged through `toPromise` only after physical drain. Cancellation during initialization MUST NOT bypass validation/reconciliation. Callbacks and monitor publications MUST execute outside mutation actions, after their checkpoints commit.

Skip/retry replacements wait for drain; whole-run completion waits for drain and host disposal. Post-abort awaits MUST NOT trigger gates, repairs, failure callbacks, or cost accounting.

Internal repairs consume the ledger budget without incrementing graph starts. Batch ready admission/dispatch intents before effects and outcome/cost/live-drain settlement before capacity release; checkpoints are synchronous safety boundaries, never monitor updates. Runtime indexes are transient; full validation remains at restore/replacement boundaries.
- Validate legacy state before migration and checkpoint migration before callbacks/dispatch. Recovery drains require proven dead-writer ownership plus positive host reconciliation; validation-shell effects fail closed. - Cancellation intent MUST durably distinguish `skip`, `retry`, `lifecycle`, and `cancel` before stopping effects. Restore applies only the latest matching drained execution's disposition: skip is terminal, retry/lifecycle restart the same activation in a new graph attempt (`restore` labels lifecycle), and whole-run cancel remains terminal. Old dispositions and presentation labels MUST NOT replenish a newer execution's budget.

Cancelled snapshots MUST acquire ownership and reconcile drains before settled cleanup; unresolved validation-gate drains retain the snapshot.
- Loop targets MUST NOT reach `fanout` or `bounded_feedback` over normal edges, including guarded paths; expansion MUST validate the combined effective topology before atomic insertion. Restore skips authored-placeholder checks only for collection children whose exact generated definitions and ownership/UUID/provenance pass regeneration against durable templates and input.

- Graphs separate authored keys and optional non-unique names from run-scoped UUID-v4 instance identities. Manifests and continuation intent MUST be checkpointed before dispatch; retry/restore retain IDs and fresh runs allocate new ones. V1 snapshots upgrade atomically before dispatch; corrupt/unknown versions fail closed.

Same-session recovery retains the exclusive writer lease. Validate scheduler/graph state and recursively re-authorize persisted nested graphs against current delegation policy before resuming.

Skip batches and explicit cancellation MUST checkpoint only coherent feedback ownership; terminal restore MUST NOT dispatch.
